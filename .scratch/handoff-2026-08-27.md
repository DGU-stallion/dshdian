## 本次完成的工作

### WebSocket 通信修复（核心问题）

**根因**：两层问题叠加
1. esbuild 把 `ws` 包解析为 `browser.js` stub（因 package.json 的 `exports.browser` 条件），导致运行时抛 "ws does not work in the browser"
2. 修复后，`handleSessionEvent` 错误地访问 `event.chunk`，实际 DSH 的 SessionEvent 结构是 `{ type, seq, time, data: { turn, step, chunk } }`

**修复**：
- esbuild 配置：`alias: { "ws": resolve("node_modules/ws/index.js") }` + Node builtins 全部 external
- `handleSessionEvent`：从 `event.data` 读取业务字段

### 其他修复
- `DshProcessManager.ensureProfile()`：不再依赖 `dsh plugin --help` hack，直接创建 profile 目录结构
- `tsconfig.json`：添加 `esModuleInterop` + `allowSyntheticDefaultImports`
- 添加 `ws` + `@types/ws` 依赖

### 架构关键路径（已验证通过）

```
Plugin onload
  → DshProcessManager.start()
    → healthCheck → already running? → trigger("started")
    → OR: findDsh() → ensureProfile() → spawn dsh --profile dshdian --port 3180 --no-open
  → on("started") → client.start(sinks)
    → openStream("mux")  → ws://localhost:3180/api/events.mux  ✓
    → openStream("host") → ws://localhost:3180/api/events.host  ✓
    → rpc("host.describe") ✓
    → emitState("connected") → view.setStatus("connected")
  → 用户发消息
    → rpc("session.prompt")
    → mux frames arrive: session/event → event.data.chunk.text → appendStreamToken
    → turn/end → finalizeStreamingMessage
```

### DSH SessionEvent 真实结构（关键发现）

```json
{
  "type": "assistant/chunk",
  "seq": 15,
  "time": 1787824739238,
  "data": {
    "turn": 1,
    "step": 1,
    "chunk": { "type": "text-delta", "index": 0, "text": "Hello" }
  }
}
```

业务字段在 `event.data` 中，不在 `event` 顶层。
